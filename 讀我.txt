⏩⏩⏩ 【交接段】(2026-07-31,HFP 機)📍 修「在外面按 GPS 一定拿不到定位」⏩⏩⏩
狀態:**v12 已修好、12/12 閘門綠 + 舊版反向復現過。**
使用者回報:「當我在外面時,按下用 GPS 開始找羊,都會出現『拿不到定位(要允許權限)』,就不能玩了。」
★ 根因**不是權限**(他的權限是開的),是 startGPS 舊碼 `timeout: 10000` 太短:
  `enableHighAccuracy:true` 且 `maximumAge` 沒給(預設 0)= 強迫手機**重新開 GPS 取一筆全新 fix**;
  戶外冷啟動(剛出門、樓房之間、第一次在這個站授權)典型 15~45 秒才有第一筆 ⇒ 10 秒必定 TIMEOUT(code 3)。
  更糟的是舊碼把 code 1/2/3 **三種錯誤全部**寫成「要允許權限」= **把使用者導向錯的解法**
  (跑去設定裡看,權限明明是開的)——所以看起來像權限 bug,其實是「等太短」。
  🔬 反向證明過:把 HEAD 版本拉出來、餵同一個「20 秒才有 fix」的情境,舊版跳出的正是使用者
     看到的那一行字、25 秒後仍卡在開場面板(=玩不了);新版同情境開場成功。
本輪做的(六件,缺一件都還是會卡):
  ① 主力換 `watchPosition`——它會**一直重試**直到拿到 fix;getCurrentPosition 一次超時就死。
     且**刻意不給 timeout**:要等多久由畫面上的計時器講,不是叫瀏覽器放棄。
  ② 等待期間有畫面:「⏳ 正在定位…N 秒(不用重按)」,15 秒後改教「走到看得到天空的地方」,
     40 秒後才提「先用測試模式也能玩」。取代舊的「按了沒反應 → 跳一行失敗就結束」。
  ③ 錯誤按 code 分辨:1=權限(附 iPhone/Android 逐步開法,並提醒**主畫面圖示是另一份權限**)、
     2=收不到訊號(講「還在試,不用重按」)、3=還在等。另外先擋 `!isSecureContext`(http 一律不給定位)。
  ④ 快取位置搶開場:另發一支低精度 + maximumAge 5 分鐘的 getCurrentPosition;
     ⚠ **±200m 以上不採用**——那種精度開場,羊會在眼前整批搬家,比多等幾秒更難懂。
  ⑤ HUD 加「📍 ±Nm」精度(>40m 轉黃):抓羊要 25m 內,不講出來就變成「走到了卻抓不到=遊戲壞了」。
  ⑥「📍 重新定位」鈕在 watch 斷掉時會**重啟定位**(以前半路進室內只能整頁重載)。
⚠ 埋過的雷:開場從 click handler 搬到 callback 裡 ⇒ 音樂**不再在使用者手勢內**。
  靠檔尾那個一次性 pointerdown unlock(按那顆鈕就解鎖了),startGPS 裡再明確補一次 SFX.unlock()。
🔬 常設閘門:`node scripts/verify-geo.mjs`(先 `npx http-server -p 5199 -c-1 .`)。
  用 stub 把「只有真手機在外面才遇到」的五種情境搬到桌機:慢定位 20 秒 / 權限被拒 / 收不到訊號 /
  快取夠準 / 快取太粗。目前 **12/12 🟢、0 pageerror**。
  ★ 以後動 startGPS / beginPlay / geoErrHtml,先跑這支,別再靠「拿手機出門走一趟」才知道壞了。
  迴歸也跑過:verify-strike 🟢(A 0.36 / B 0.24)、verify-audio 🟢(0 error)。

  清掉 inline 樣式後 CSS 那條又生效 → 按鈕永遠不見 → **等於根本抓不到羊**。
  已改成寫明確值 `display:'block'`。教訓:要顯示「被 CSS 藏起來」的元素,一律寫明確值,
  別用清空 inline 樣式去「還原」。
